# soc-theory

Theory base of a junior SOC analyst. Everything that lives **in the head**, not in the lab:
notes, self-tests, breakdowns of attacks and incidents, interview preparation.

Companion repos:
- [soc-practice](https://github.com/227x0/soc-practice) — hands-on attack → detection → triage cases
- [soc-lab](https://github.com/227x0/soc-lab) — the home lab infrastructure

Practice answers the question *"can you do it?"*. This repo answers *"do you understand it?"*.

## What's inside

| Folder | Content |
|---|---|
| `notes/` | Study conspectus: networking, operating systems, security concepts. Written in my own words — if I can't explain it simply, I don't understand it yet. |
| `tests/` | Self-quizzes: question lists with hidden answers, used for spaced repetition. |
| `breakdowns/` | Analyses of real incidents, CVEs, malware reports, news — decomposed like my lab cases but without the lab. |
| `interview/` | Expected interview questions (EN/CZ), rehearsed answers, gaps I keep hitting. |

Language: **English, compact.** Drafts in RU stay local; what gets published
is short and in English. Terms stay in English.

## Rules of this repo

1. **Own words only.** Copy-paste from courses doesn't count as a note.
2. **One idea per note.** Big walls of text are books, not notes.
3. **Every note ends with a self-test question.** If I can't quiz myself on it, the note isn't finished.
4. **Mistakes stay visible.** Corrected notes keep the wrong version with a strike — that's how progress looks.
